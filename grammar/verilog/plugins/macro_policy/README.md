# macro_policy — 宏处置策略（能力组件）

> 引擎只做文本操作，不判定"此处该怎么处置"；判定是语言知识 → 本组件通过
> `[capabilities] macro_policy` 向引擎暴露策略函数（契约见
> `preprocessor/README.md`「宏处置策略（插件能力）」）。

## 判定表（依据都来自真实语料）

| 调用点事实 | 处置 | 依据 |
|---|---|---|
| 空体宏 + 独占一行 + 行首 | `line` | 行首空体宏是声明修饰符（`` `FORMAL_KEEP reg [3:0] q; ``）：文本替换会造出"标识符 + 声明"相邻，破坏 decl 解析 |
| 空体宏（其余位置） | `inline` | 替换为空会丢调用原文（tv80 `` `TV80DELAY ``）；行内注释锚是 trivia，parser 跳过 |
| 非空体 | `splice` | check 要宏体语义（否则宏体内语句不可分析）；还原走宏区间 raw 拼接 |

> 判定**优先序**：空体宏形态在最前（它们靠锚保留调用原文），然后才是非空体宏的
> 宏体铺进流。

## 已知边界

- 处置枚举（`splice` / `line` / `inline`）是引擎定义的**机制面**，与铺条目
  的 `mode` 同词——引擎只执行，不判定。
