# macro_policy — 宏处置策略（能力组件）

> 引擎只做文本操作，不判定"此处该怎么处置"；判定是语言知识 → 本组件通过
> `[capabilities] macro_policy` 向引擎暴露策略函数（契约见
> `preprocessor/README.md`「宏处置策略（插件能力）」）。

## 判定表（依据都来自真实语料）

| 调用点事实 | 处置 | 依据 |
|---|---|---|
| 空体宏 + 独占一行 + 行首 | `line` | 行首空体宏是声明修饰符（`` `FORMAL_KEEP reg [3:0] q; ``）：token 替换会造出"标识符 + 声明"相邻，破坏 decl 解析 |
| 空体宏（其余位置） | `inline` | token 替换留 `tpc_marker_N 1'b1` 相邻原子（tv80 `` `TV80DELAY ``）不可解析；行内注释锚是 trivia，parser 跳过 |
| 非空体 + 语义模式（check / lint 路径） | `splice` | check 要宏体语义（否则宏体内语句不可分析）；还原走宏区间 raw 拼接 |
| 非空体 + 行首 ∧ 行尾（独占一行） | `token` + `append=";"` | 语句体宏原文常无分号（ice40 cells_sim `` `SB_DFF_INIT ``），锚名是标识符、裸标识符不是合法语句 → 补分号 |
| 其他（行内 / 表达式位） | `token` | 锚随 AST 确定位置，还原按锚名整串匹配 |

> 判定**优先序**：空体宏形态在最前（它们在任何模式下都靠锚保留调用原文），
> 然后才是 semantic（语义展开）与"独占一行补分号"。

## 已知边界

- `append=";"` 对"宏调用独占一行但夹在跨行表达式中间"（`a +` / 宏 / `+ b;`）会误补——
  语料与真实代码均无此形态（属坏风格），可接受。
- 非语义路径（token 锚）当前无引擎调用方（pipeline/analyzer/linter 都走语义展开）；
  本表该分支保持完整，供 `semantic=False` 的直调方（测试/嵌入）使用。
- 处置枚举（`splice` / `line` / `inline` / `token`）是引擎定义的**机制面**，与铺条目
  的 `mode` 同词——引擎只执行，不判定。
