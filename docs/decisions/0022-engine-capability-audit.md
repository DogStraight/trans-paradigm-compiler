# ADR-0022: 刻度完成后的引擎能力面全项审查（矩阵 + 第二语言复用判据）

- Status: accepted
- Date: 2026-10-21

## 背景

作者 2026-10-21 定调：**C 包不是"多一门语言"，而是对引擎抽象的持续压力测试**——"每多一门语言
就多一次不同的处理，就存在没有被审查的抽象"。同时指出两个薄弱面：**文件链接 / 入口点**、
**依赖特定语言的精化基座**（`pre_scan` / raw 承载与理解 / sites 等）——它们"其实可以被内置化为
引擎能力面"。刻度（`PROGRESS.md` 7→9）的用途正是**为 P3 增量解析 / 高性能组件这类高难度动作
做准备**；刻度完成后做一次**全项审查**，而不是在未审查的抽象上继续盖楼。

反例现场（避免口头声称；详见 `docs/gaps/gap-engine-abstraction-audit.md` 矩阵）：
`enabled` 只门控声明面 ⇒ C23 合法的 `_Static_assert(1)` 落不了地；同构造异拼写靠"各写一条
同形规则"复制（两个节点名）；C 的 `#include` 链路、Verilog 的 `module_index`、CLI 单入口 /
`ProjectChecker.check(paths)` 多入口三套并存。

## 决策

1. **时机**：主线 1 刻度 7→9 完成后、P3/性能类改动之前，执行**一次**全项审查（不按需零敲——
   零敲看不到"同一抽象被两门语言各自实现"）。
2. **判据只有一种形式**：「能力 × 语言」矩阵 + **第二语言复用实验**。矩阵每格四态：
   **原样** / **新声明键**（抽象成立）、**新引擎代码**（leak 候选）、**逃生门**（必须消灭或
   降级）。leak 候选的证伪 = 在第二门语言上只用配置表达同一能力：只改配置即成立 ⇒ 抽象成立；
   引擎必须再改 ⇒ 记 leak 并给内置化方向。
3. **台账**：`docs/gaps/gap-engine-abstraction-audit.md`（矩阵 + 每行证据/复现 + 内置化方向 +
   审查完成判据）。本 ADR 只定方法与时机，台账只记现状——二者不互相复制。
4. **平日维护**：每个循环若碰到新的"语言特化处理"，顺带在台账补一行（调查轮性质、不单独汇报）；
   审查轮一次性出结论与立项清单。
5. **内置化不做"为通用而通用"**：只对"复用实验要求改引擎"的格子立项；只有一门语言需要的形态，
   留在语言包并标「接受」。

## 权衡

- **代价**：矩阵要持续维护；每行必须带证据（否则等于口头声称），行数增长受 gap 档 200 行预算约束
  ⇒ 只登记有语言间对照价值的行。
- **被否备选**：按需零敲——缺全局视图，无法发现"同一抽象被两门语言各自实现"。
- **被否备选**：以"架构看起来通用"口头收尾——不可证伪，与本仓证据文化冲突（循环 #33 的教训即
  "未经对照的因果句会入版本库"）。

## 验证

- **方法可证伪**：台账每行有"四态判定 + 证据/复现 + 状态"；判定错误由第二语言复用实验复查。
- **审查完成判据**：矩阵无"逃生门"、无"新引擎代码只服务一门语言"未处理项；或逐项给出
  「不做 + 触发条件」。台账清空即删本 ADR（与 decisions 目录"完成即删"一致）。
- **纪律门禁**：`docs/gaps` 行数预算与引用一致性由 `tests/policy` 守（本决策为纯文档/方法）。
