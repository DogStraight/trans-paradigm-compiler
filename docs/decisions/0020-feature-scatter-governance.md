# ADR-0020: 功能散点治理——度量先行、单一来源、能力协商

- Status: accepted
- Date: 2026-09-25

## 背景

"加一个功能要改多少处、上游一变语言包要跟着改多少"长期只能凭感觉说。立项时先做了
实测（2026-09-25，工具与全库计数），把混在一起的抱怨拆成**三个机制不同**的痛点：

- **P-A 登记散点**：一条诊断码散落在最多 20 个文件；加一条规则族改 6 个文件（含引擎侧
  `analyzer/checks.py`）；`declare_cfg` 18 处调用**几何全在引擎模块内**、`grammar/` 侧 0 处。
- **P-B 上游契约耦合**：ADR-0019 精化基座重构全程，引擎边界调整一次 → `grammar/` 11 +
  `tests/` 11 文件被迫跟着改；代价记在**语言包账**上，且随包数量线性放大。
- **P-C 兼容只有粗粒度开关**：`[engine] api = "0.1"` 是**整条 API 线**——引擎 minor 一动
  所有包都被拦（三包都只声明 `0.1`），报错还说不出缺哪一项。

现状陈述与逐条实测见 `docs/gaps/gap-feature-scatter.md`（本档只记决策）。

## 决策

**D1 度量先行，且度量"未处置的欠账"**。任何收敛动作之前先有数字：`tools/feature_sites.py`
按功能分族（检查规则 / 语法构造 / 能力位 / 配置键）枚举现存实例、扫出"提及它的文件"并按
角色归类（插件内 / 引擎侧登记 / 行为基线 / 测试 / 文档）。判据**不是"文件多"**——测试与
文档本来就该多；判的是**同一事实被写在 ≥2 个必须手工保持同步的位置**。口径沿用
`policy/structural_budget.md`：逐项下结论后从预算里出去，"保持"是结论不是"没看"。

**D2 单一来源优先：同一事实只允许一处定义，其余派生或校验**。提取逻辑本身也要单一
（`tests/_rule_codes.py` 被两个门禁共用；各写一份提取器就是新的散点）。

**D3 "校验 / 派生 / 接受"三分**。机器可读的登记点 → 接门禁校验（或改读单一来源）；
**散文不接逐 token 校验**——文档里的码会成范围（`NC001-NC010`）与历史提及出现，逐 token
校验是误报机器，属**有意接受的边界**，由文档门禁 + 人工复核承担。判断标准始终是
"**是否必须靠人记着同步**"，不是"文件里出现没出现这个码"。

**D4 契约版本化到能力粒度**。`[engine] uses = ["lexer.token_ext.v1", …]` 逐项声明依赖的
引擎契约面；能力表与版本在 `core/engine_capabilities.py`；协商报错**点名**是哪一项
（包版本 vs 引擎版本）。升版判据：只有"该能力对语言包**可见地**变了"才 `+1`，纯内部
重构/性能/文案**不**升——否则受影响面被自己放大成常态，协商退化成原来的粗线。

**D5 不留兼容，且收敛声明必须可审计**。旧 `api` 线删净（残留由"未知键"在加载期拦下）；
"已收敛 / 判保持"登记每条须有 `reason` + `source` 指向**真实存在**的门禁，且不得空转
登记（写进表却没出现在基线里即红）——否则洗欠账只要写一行 JSON。

**D6 断言分工**：**协商语义**（合法/非法/点名报错/未声明不误伤）在部件测试；
**仓库不变式**（派生集 ⊆ 声明集、能力表形态）在 `tests/policy/`。同一断言不在两处写。

## 权衡

**付出的成本**：

- 多了一层登记表与门禁（`feature_sites_kept/converged.json` + 三个新门禁），
  且**门禁本身要可证伪**才作数——每条都要有"注入坏值即变红"的实测，这是额外工序。
- `uses` 清单需要随包清单更新；用"机械推导 + 门禁查漏"把它从"靠记忆"降为"跑一次工具"，
  但**没有消除**这层工作。
- 散文边界（机制文档码表、docstring 枚举）仍靠人工复核，工具量不出来。
- 升版纪律要自律：放宽判据（见 D4）会让整套机制悄悄失效。

**被拒绝的备选**：

- ① **统一 manifest / 代码生成器**（把全部登记点收敛成一份清单再生成）：配置面膨胀风险本仓
  已付过学费（`docs/references.md` 数字形态 7 字段 × 4 形态块的实证）。本议题只做
  "把已有登记点收敛成一处"与"把已声明的事实拿去校验"，**不新增表达语言**。
- ② **逐 token 校验文档散文**：误报机器（见 D3）。
- ③ **保留 `api` 线双跑兼容**：与硬约束"不留向后兼容"冲突，且双路径漂移是本仓已记录的债。
- ④ **按"事实分族"重构**：ADR-0019 已实测此路不通（改按**消费簇**切）——同一教训在此复用：
  分组要按"谁真的会一起改"。
- ⑤ **只做度量不做收敛**（只统计不设门禁）：度量会随热度衰减，欠账重新隐形。

## 验证

分三步独立落地、各自验证（每步都有可证伪的门禁实测，非声明）：

| 步 | 内容 | 证据 |
|---|---|---|
| 1 | 接触点计量 + 预算基线（`tools/feature_sites.py`） | 四族基线：`check` 24 实例/散点 56｜`syntax` 7/0（只在跨阶段 2–11 文件）｜`capability` 3/30｜`config` 14/26 |
| 2 | 诊断码单一来源 + 三个机器可读登记点接门禁 | `check` 族预算 **56 → 16**（已收敛 40）；注入假码 `ZZ999` → 门禁 **1 failed**，还原 **0**；三处实际校验 11/13/7 条码 |
| 3 | 能力清单协商替换整条 API 线 | 三包清单 c4 5 / verilog 14 / yaml 2（全部由清单推导）；漏声明 `parser.pratt.v1` → 门禁 **1 failed** 并点名，还原 **0**；无关能力升版**不误伤**只声明别项的包 |

回归面：全量 **2213 passed / 8 skipped**；`-m smoke` **433 passed**；
`tests/policy` **143 passed, 1 skipped**；`feature_sites --compare` ✓ 无散点增长。
