# 注释"AI 味"审查方案（comment_smell rubric）

> 用途：对 tpc 各部件注释做**味道审查**——注释是稀释成 AI 味/模板化的空话，
> 还是携带真实的人味（为什么、历史、权衡）。
> 定性审查，**不是作者判定**，**不改代码**；误报责任在评审者。
> 类别：机制（评审工作流）。前人方案调研见 `references/comment_smell_survey.md`。
> 正面基线：`coding_style.md`（注释语言/格式约定）——风格合规 ≠ 没味道，
> 一句格式规范的注释照样可以空洞。

## 七个维度（证据导向）

1. **冗余复述**：注释复述代码显而易见的内容（`i += 1` 旁写"自增 i"）。
   判据：删除该注释，信息是否零损失。
2. **空话/无信息量**：只声明"重要/注意/为了可维护性"，不给具体内容。
   判据：读者能否据此知道**该怎么做/为什么**。
3. **AI 套话**：命中套话词表（见下），或翻译腔（"众所周知/显然/值得注意的是"）。
   **词表只是粗筛**——命中不判罪，需结合上下文；同一语义用词朴素则不算。
4. **模板化 docstring 八股**：每个函数机械地"功能/参数/返回"三段式，无增量信息。
   判据：把所有 docstring 的"功能"句抽出来，是否每句都像同一句话换词。
5. **过度解释/教程腔**：解释读者本已掌握的通识（"解析器就是把 token 变成树"），
   不针对本代码的特异性。
6. **缺失 why（人味维度）**：只讲机制不讲理由/权衡/被否方案/历史坑。
   判据：本仓库文档体系重视"为什么/历史/权衡"（`docs/README.md` 读者维度、
   `coding_style.md` 注释风格），注释缺 why 本身就是味道——即使措辞毫无 AI 味。
7. **语气异常**：过度礼貌/讨好（"请务必"、kindly note）、过度自信（"毫无疑问"）、
   企业腔（"我们的目标是…"）。

## 套话粗筛词表（中英各举，非穷举）

- 中文：值得注意的是 / 需要注意的是 / 总而言之 / 简而言之 / 综上所述 /
  众所周知 / 显然 / 此外 / 因此 / 优化 / 健壮性 / 优雅 / 无缝 / 一站式 /
  赋能 / 高质量 / 可维护性（无实指用法）
- 英文：Note that / It is worth noting / In order to / Furthermore / Please note /
  leverage / robust / seamless / ensure / crucial / essential / effectively /
  simply put / ultimately / comprehensive

> 判定纪律：词表命中 → 回到上下文看它是否**有实指**。有实指（如"可维护性——
> 因为此字段被 3 处消费，改名需全量 grep"）不算味道；无实指才算。

## 严重度

- 轻：个别实例，不稀释阅读
- 中：成片出现，信息密度下降
- 重：整文件八股化，注释沦为摆设

## 人味评分（0-10）

按"为什么/历史/权衡/被否方案/个人语气"在注释中的**密度**打分，与措辞是否 AI 味无关：
- 0-3：纯机制描述，无任何判断痕迹
- 4-6：偶有 why，但机制描述为主
- 7-8：权衡/历史/坑常态化出现
- 9-10：几乎每条注释都在回答"为什么"，机制描述只为铺垫

## 输出格式（评审 agent 按此产出）

```markdown
## <部件> 总体判定
- 味道等级：轻/中/重
- 人味评分：N/10（一句话理由）
- 命中：x/y 文件有"中"以上发现
## 证据清单（按严重度）
[文件:行] 引文
- 维度：1-7；严重度：轻/中/重
- 为什么算味道：…
- 改写建议（仅中/重，每文件 ≤2 处）：…
## 人味正例（保留样本）
[文件:行] 引文 — 为什么这是好注释
## 边界（不确定项 / 非 AI 味问题，单列）
```

## 审查工作流

1. 每个部件一个 agent（或人工），逐文件读注释（模块/函数 docstring +
   行内 `#` + TOML `#` 注释）；`Doc:` 行是仓库对齐约定，不算味道。
2. 证据必须带 file:line + 引文；**无证据的判定无效**。
3. 中/重发现给改写建议（只示范，不落盘）。
4. 汇总：人味评分按 why/历史/权衡密度打，与措辞是否 AI 味正交。
5. 边界事项单列：措辞差但非 AI 味、无法判断、与代码不一致的注释。

## 诚实边界

- **AI 味 ≠ 错误**：一句 AI 味注释若信息准确，记"轻"即可，不必上纲。
- **误报真实存在**（survey §6 案例）：拿不准的标"边界"，不硬判。
- 本方案是定性 rubric，不是检测器；不承诺召回，只承诺证据。
- 单条注释无结论意义，结论只在"部件级密度"层面给出。
