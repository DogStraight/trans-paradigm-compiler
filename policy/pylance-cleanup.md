# 静态检查清零（Pylance / pyright）

> 制度层：**改过哪几个 py 文件，收尾前就清哪几个文件的静态诊断**。
> 与门禁的关系：**不进日常门禁**（依赖 LSP/编辑器环境，非零依赖命令），
> 定位同 `tools/check_coverage_delta.py`——人工/agent 按需跑的自查工具。

## 为什么定这条

引擎改动多为跨部件签名变更（匹配器、管线阶段、协议常量），**静态诊断是这类
改动最便宜的回归探针**：改了谁、谁的类型就不再成立，Pylance 立刻能看见。
日常门禁跑 pytest 只能覆盖"有测试断言到的路径"；类型/未定义名/参数不匹配
这类问题是 pytest 的盲区（运行时才炸，或者永远不炸）。

## 怎么做（按改动文件，不要求全仓清零）

1. **列改动的 py 文件**：`git diff --name-only HEAD~1 -- '*.py'`（或对未提交
   工作区 `git diff --name-only -- '*.py'`）。
2. **逐文件取诊断**（agent 侧，Pylance MCP）：
   - 单文件：`textDocument/diagnostic`（`{ textDocument: { uri } }`）；
   - 全仓概览：`workspace/diagnostic`（`{}`，返回按文件分组的 full items）。
   人类/CI 侧等价物：`pyright --project pyrightconfig.strict.json <files>`。
3. **清零判据**：改动文件的新增诊断必须为 0；**既有诊断**（改动前就存在）允许
   保留，但若在本次改动行附近，优先顺手清掉。无法清零的逐条写明理由
   （例：协议签名参数必须保留形参 → 用 `del` 显式声明不消费）。
4. **共同收尾**：清零 + 该部件测试通过（`pytest tests/<部件>`）。

## 常见处理手法

- **协议签名参数**：形参必须存在但本实现不用 → 函数体首行 `del x`（显式声明
  意图，同时消除"未使用"诊断），不要下划线改名后又忘掉语义。
- **re-export**：模块被外部按符号导入但本文件看似"未使用" → 加进 `__all__`
  （显式导出清单），这是唯一正确的"用它"。
- **死代码 / 死配置**：先确认无引用（A1 判据）再删，不靠抑制注释续命。
- **类型注解**：`list` / `dict` 裸泛型补齐参数（`list[str]`）；`Any` 返回值按
  真实契约收窄，收不窄就写明为什么是 `Any`。
- **抑制注释**（`# type: ignore`）是最后手段：必须带具体错误码 + 一行理由，
  且**不允许**用在整个文件上。

## 与其它制度的衔接

- 与 `doc-alignment.md` 的删除判据共用："这条诊断对应的代码/配置能不能删"仍走
  A/B/C 判据，静态诊断本身不是删除依据。
- 与 `coding-style.md` 共用命名/分区规则：清零动作不得引入不符规约的命名。
