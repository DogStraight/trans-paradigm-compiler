# structural_budget.md — 结构欠账的度量与停止判据

> 定位：外部裁判（Bifrost）按**阈值**报命中——修掉一批，阈值附近立刻露出下一批，
> 建议"无穷无尽"。本文档把它折成**一个可跨时间比较的标量 + 一组决策规则**，
> 回答两个问题：**这次改动值不值得做**、**主线何时收口**。
> 度量工具：`tools/structural_score.py`（需外部二进制 bifrost，见 `bifrost_audit.md`）；
> 基线文件：`tools/structural_baseline.json`。

## 一、为什么不能按"命中个数"记进度

阈值型指标有两个病：**① 个数在阈值附近抖动**（CC 10.9 → 10.1 仍算命中，实际没改善）；
**② 没有上界**（把 CC=11 的 30 个函数拆完，CC=10.5 的 30 个会顶上来）。
所以本口径一律记**超额量**：`Σ max(0, 实际值 − 阈值)`——有下界 0，且只被真实改善减少。

## 二、五条规则（把无穷尾巴切成有限清单）

| 规则 | 内容 | 理由 |
|---|---|---|
| **R1 内部线 = 阈值 × 1.5** | 只有 **CC > 15** / **认知 > 23** / **函数 > 120 行** 才算"必须处理"；阈值与内部线之间一律**保持** | 工具阈值是**提示线**（提醒"这里值得看一眼"），不是整改线；提示线的存在理由是"覆盖潜在问题"，整改线的理由必须是"收益 > 代价" |
| **R2 模块即类豁免** | 类体 ≥ 60% 文件行 → 按**模块**度量（模块 > 800 行才超标）；否则按类体度量（> 450 行） | 类体 ≈ 整个文件时，拆类不缩小阅读/验证面（部分文件甚至变大）——只有拆**模块**才有收益。实测比例：`RuleMatcher` 92%、`Lexer` 88%、`Discovery` 91% |
| **R3 实体级重复门槛** | 重复对 **tokens ≤ 40** 判保持，不计入欠账 | ≤40 token 的重复是"具名入口 → 共享实现"的残留样板（共性已抽），合并只能靠删函数名，方向与可读性相反（`bifrost` 分类 A–C 类，58 对） |
| **R4 制度执行者豁免** | 两侧都在 `policy/` 的重复对不计入 | 门禁脚本刻意各自独立、可单跑；抽公共会把门禁耦合（已有定调） |
| **R5 热点加权（排序，不记分）** | 动手顺序按 `analyze_git_hotspots` 的 churn × complexity 排，冷文件超标排在后面 | 同等的欠账，改在热文件上的收益才真实（冷文件可能几年不动） |

## 三、度量：结构欠账分 S

```
C = Σ_f max(0, CC_f − 10) + Σ_f max(0, 认知_f − 15)          复杂度超额
L = Σ_f max(0, 函数行_f − 120)                                函数规模超额
  + Σ_c max(0, 规模_c − 阈值_c)                               类/模块规模超额（阈值按 R2）
D = Σ_p max(0, tokens_p − 12)  （p 通过 R3/R4）                实体级重复超额
S = C + L + D                                                 越低越好
```

- 分块常量固定在工具里（`CC_CHUNK=20`、`CLONE_CHUNK=30`）：外部工具**分块会改变输出**
  （长方法/上帝对象工具每调用最多分析 25 个文件；重复工具的分块影响"最佳克隆对"选取），
  不固定就没有可比性。
- 扫描面：非 tests 的受控 Python 文件（排除 `tests/`、`_drafts/`、`.agents/`、构建产物）。

## 四、收益量化与决策规则

| 量 | 取法 | 用法 |
|---|---|---|
| **ΔS** | 改动前/后各跑一次 `tools/structural_score.py`（或对同一窗口用 `--compare`） | 这次改动的**结构收益**（单位：欠账点） |
| **改动规模** | `bifrost --tool score_diff` 的 `geometry.insertions + deletions` | 收益的代价面 |
| **ROI** | `ROI = ΔS / 改动规模` | **ROI < 0.05 不做**（起始标定值，两次实测后定稿）：即"改 100 行至少降 5 点欠账" |
| **验证面** | `score_diff` 的 `verification.untested_fraction` + `without_direct_test_reference` | 单次改动的报告项（不进 S）：改了却无直接测试引用的生产符号占比 |

**不做也必须留痕**：判"保持"的项写入 `_drafts/bifrost/dispositions.md`（理由 + 证据），
不许出现"没人管"的项——"保持"是结论，"没看"不是。

## 五、停止规则（满足任一 → 本主线收口）

1. **规则过滤后无待做项**：所有命中都被 R1–R4 过滤成"保持"（即当前状态）。
2. **新增即回归、存量即池**：冻结基线后（`--save`），只有**新命中**才算回归（`--compare`
   退出码 1）；存量项按批次消化，不做无穷清扫。
3. **ROI 连续不达标**：连续两批改动的 ROI < 0.05 → 停止结构线，改由行为面（缺陷/需求）
   驱动。

## 八、五个杠杆：复杂度只能从哪里降（"不影响表述能力的最低复杂度"）

复杂度的**真实**下降只有五条来源，其余动作（提函数、拆类、换文件名）只是**重排**——
认知分会降（嵌套变平），但总信息量不变（`_build_scope_kind_map` 拆成三段，语言事实还是那些）。

| 杠杆 | 判据：删掉它是否损失"一条语言事实 / 一种输入形态"？ | 本仓实测剩余 |
|---|---|---|
| **1 删除需求** | 是 → 保持（删了就是删功能） | **0**（纪律已机器化：完成即删、不留兼容垫片；规则覆盖由 `tests/policy/test_rule_coverage.py` 守） |
| **2 删除死代码** | 否——不存在任何引用 | **0 处**（实测：私有定义名在全仓 512 文件 / 13798 词表中只出现 1 次 = 0；B-B4c 已删 3 个不可达门面方法） |
| **3 简化接口** | 否——公开面大于使用面 | **48 项**（公开但无跨模块引用：引擎 41 / 语言包 7）**+ 22 项**全仓零引用的公开符号**待逐条定性**——多为**动态分派面**（`@register` 原语 `eval_*`、preprocessor 的 `handle_*`、插件 handler 名），文本级引用扫描对动态分派会失真，须看调用方式或用符号级探针（另有 392 项确认被产品侧引用） |
| **4 消除重复** | 否——同一实体写了两遍 | **20 对 / 940 点**（>40 tok；≤40 tok 的 88 对是入口样板，判保持）。含 2 对真重复：同语言包内两份常量表达式解析器 |
| **5 统一抽象** | 否——分支在算同一件事的不同变体（表化/骨架化可替） | **约 4–6 项 / 89 点**（CC>15 的 4 项 + 认知>23 的 2 项） |

**"重排"不是收益**：本仓 B-F 十批（CC 150→12、认知 157→5）主要是**重排**——把嵌套结构提成
独立函数，使每个函数的认知分下降、长函数消失；语法事实、分支数、语言知识面一条没少。
它们仍然值得做（改动的局部性、可测性、命名可读性都变好），但**不要记成"复杂度下降"**，
否则会误判"还剩多少"。

**按五杠杆核账（2026-09-20 实测）**：
- 可动：重复 20 对（D 940，机械、低风险）→ 接口收窄 48 项（不改 S，降阅读面）→
  统一抽象 ~4 项（C ~89，中等风险：新抽象自身要更简单才划算）→ 拆模块 4 项
  （L 536，高成本：`Lexer` 1004 / `RuleMatcher` 989 / `BoundaryScanner` 549 / `Parser` 494）
- **侧别分布（引擎 vs 语言包，2026-09-20 实算）**：重复 20 对 = 引擎 13 / 语言包 7；
  接口收窄 48 项 = 引擎 41 / 语言包 7；复杂度 18 项 ≈ 引擎 9 / 语言包 9；
  规模 4 项 = 引擎 3 / 语言包 1。→ **机械项集约 60 项在引擎侧，但没有一项是大改**
  （改名/合并同形助手）；语言包侧 ~24 项同样机械。**真正需要决策的只有两项架构工作
  （L1 渗透复审、L2 基座重设计），且都在引擎侧。**
- 不可动（表述能力所需）：**逐规则/逐变体的分支集**——`boundary._build_scope_kind_map`(21/52)、
  `_collect_block_rule_bounds`(29)、`renderer.doc` 变体分派族；以及"模块即类"里承载的
  语言事实面。删/并它们等于删语言支持。
- 现实目标区间：**S 1595 → 500 ± 200**（消重复 + 收窄接口 + 两项模块拆分 + 2 项统一抽象）；
  再往下就要动语言事实或做无收益的分文件，**收益递减**——这是停止线的经验位置。

## 九、与其它门禁的关系

- **不进日常门禁**：需要外部二进制、分钟级；本口径只用于"结构性改动"的收益评估。
- **行为面仍由仓内门禁负责**：测试（`pytest`）、真实语料字节对拍、
  `tests/e2e/eval_diag_baseline.py` 误报基线——结构分再低也不能替代行为证据，
  反之亦然。两者是**并列的两套证据**（结构分低 ≠ 行为对；行为对 ≠ 结构可维护）。
- **判据改口径**：改本文档的常量或公式，须同步 `tools/structural_score.py` 的常量，
  并**重写基线**（口径变了，旧基线不可比）。
